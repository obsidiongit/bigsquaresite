## Design direction

- Light section (`theme="light"`, `anchor="solution"`), `py-section-y-lg`. Content `relative z-10`. Width: EDGE, no Container, no rails, no Nº.
- Headline in Bluu Next (`font-display`) at `--text-statement`: the page's single statement-scale moment, relocated here from the retired v2 problem headline. Left-aligned.
- Header row under it: intro at `--text-lead` in `--sec-mid` capped ~52ch left; the two Pills right-aligned on the same baseline row (stack on mobile).
- Cards: 3-up equal grid, `gap-6`. Each `bg-surf rounded-[24px] border border-sec-line p-6 md:p-8`. Top: the widget vignette on a `bg-paper rounded-[16px]` inset panel (inner elements radius 8). Below: title at `--text-h3` Apfel 700, one-liner at `--text-body` in `--sec-mid`. Cards never hover (not links).

## Widget specs (timing measured from the reference videos, then calmed)

House rules for all three: pure CSS `@keyframes` (new `wgt-*` block in globals.css, groundwork), transform/opacity only, `--ease-house`/`--ease-swoop`, no bounce. One shared loop duration per widget; every element sequences via percentage keyframes + `animation-delay`, so the card is a single synchronized timeline with a seamless repeat. Root class `.wgt`; paused unless `data-play` (set by `useInView`). Reduced motion: CSS kill + component renders the settled end frame. No fake numbers, no fake names (their videos use "Eric" and real-looking dates; ours never do).

### 1. Calendar (No Long Term Contracts)
Reference: `Calendar-Week.mp4`, 3.05s, 3 beats. Ours: **4.5s loop, 3 beats of 1.5s** (calmer hold).
- Panel: month label between two chevron buttons, hairline, then a 5-cell week strip: day-name over day-number (Fri 1 through Tue 5), cells rounded-8.
- Beat cycle: month label swaps (Jan, Feb, Mar analogs; generic "Month 1" style is too fake-averse even for us: use real month names, a calendar is not a claim), active cell moves (cell 3, cell 4, cell 1), each transition a ~300ms cross-fade of the strip + label.
- Active cell: `--acc` fill, white numeral. Idle cells: `--paper` on the inset, `--sec-mid` day names.

### 2. Task list (Transparency)
Reference: `Task-List.mp4`, 3.25s, sequential check-off. Ours: **5s loop**.
- Panel: "Tasks" title row with a small glyph, hairline, two task rows: circle checkbox, task title (Apfel 500), one-line sub (small, `--sec-mid`), a tag chip + a blurred value-bar where their fake date sits.
- Task titles generic and true to what we do: "Launch the search campaign" / "Send the monthly report". Chips: "Paid Search" / "Reporting" in mono, `--surf` ground. No person names, no dates.
- Beats: 0 to 1.5s both unchecked; ~1.5s row 2's circle fills `--acc` with a white check (scale-in 200ms), title strikes through (scaleX left-origin 250ms) and row dims to 45%; ~3s row 1 checks the same way; ~4.5s quick 300ms fade-reset; loop.

### 3. Channel bars (Full Approach)
Reference: `All-Channels.mp4`, 3.30s, grow-and-hold. Ours: **5.5s loop**.
- Panel: "All Channels" title row with chart glyph, hairline, 3 labeled bar rows + faint tick gridlines. Labels: "Paid Search", "Calls", "Social" (generic service words, not platform brands). Ticks unlabeled (no fake axis numbers).
- Beats: 0.5s axes only; bars grow left to right (scaleX, 600ms `--ease-swoop`, 120ms stagger) to fixed widths ~85/60/35%; hold ~3.5s; 300ms retract-reset; loop.
- Bar color: this is the one place the widget system uses more than one fill. Stay on brand: `--acc`, `--acc2`, and `--mid` (never a traffic-light trio).

## Motion

### The card sweep (v3.2, Brad 2026-08-24, PINNED in round 4)
The section's fun beat and the companion cube's route through it. Desktop only (the mobile journey exits back at featured work):
- The cube crosses the header high on the right, then DIVES fast down the right edge and parks OUT OF FRAME below the card row "in preparation" (Brad round 3: a leisurely descent meant the beats finished with the cards "already basically scrolling past").
- THE PIN (round 4: "stop the scroll with this in full viewport so we can see the cube animation... unfreeze after the cube gets all the way to the left side"): the whole composition is a sticky child inside `SolutionStage` with a 130svh runway spacer (`SWEEP_RUNWAY_VH`), the hero/work-panel architecture. The runway scrubs the sweep 1:1: the cube rises from below frame at the right edge (p 0.02-0.2), sweeps FLAT right-to-left under the frozen cards with beats at p 0.3/0.5/0.7 (Full Approach, Transparency, No Long Term Contracts), then dives back below frame at the left edge (p 0.7-0.97), and the pin releases.
- During the pin, the canvas positions the cube in PX off the frozen grid's live column centers + a lane below the row (Tracker, `lib/solution-sweep`), so under-card alignment is exact at any width; the path starts and ends below the frame, so both handoffs to the waypoint journey are off-screen. The sticky top is MEASURED (viewport minus composition minus lane, clamped [-180, 88]): tall viewports pin the full composition; short laptops let the headline run off the top rather than sink the sweep lane below the fold.
- The whole runway is a FREE-PARK zone (7.4 round-9 rule: the cube is alive at rest everywhere in it) — no checkpoint bands.
- Fallbacks collapse the runway to 0 (mobile, reduced motion, no WebGL): with zero room the sticky child never pins and the section scrolls natively; desktop-no-cube falls back to per-card top-down underlines like mobile.
- As it crosses under each card's title, that title draws a `RoughAnnotation variant="underline"` in `--sec-acc`: the SAME hand-drawn boiling scribble system as the hero circle and the featured work box (Brad's explicit call; a bespoke smooth sine underline was rejected as "absolutely silly"). TWO-WAY via the new `rearm` prop (Brad round 2: they must "pop up one by one as the square slides under that actual card", never sit pre-drawn): each draws (1.2s) as the cube crosses, boils while lit, retracts (0.5s) on scrub-back, replaying every pass. Rearm keeps the svg mounted, so undrawn paths snap opacity 0 after retract (a zero-length round-cap path otherwise renders a dot).
- Bottom pad `pb-[max(140px,16svh)]` (round 2's deep 28svh pad was superseded by the round-4 pin: the sweep now completes inside the runway, so the pad only breathes between the release and the Search occluder).
- Three underlines share this viewport: a deliberate, Brad-approved exception to the 1-annotation-per-viewport budget (they draw one at a time behind the cube).
- Timing beats live in `lib/solution-sweep.ts` (SWEEP_UNDER as fractions of PIN RUNWAY progress, plus the shared `sweepPin` rect clock) and are consumed by the canvas Tracker, the DOM triggers in SolutionCards, and SolutionStage alike: all three measure the same stage/pin elements each frame, so cube, ink, and pin cannot drift.
- The grid carries `data-cube-anchor="solutionCards"` so the sweep hugs the card row regardless of the header's height.
- After the sweep the cube drops off the row's left edge and is swallowed by the Search section's rising ground (Search and ProofBand paint at `z-[6]`, above the canvas); it stays hidden until the trust marquee. See 5b.search.md / 7.proof-numbers.md.
- Mobile: each card's underline draws on its own position (top clears 78% viewport), top-down. Reduced motion: underlines render settled, no cube, nothing draws.

- Headline BaselineReveal; header row + cards Reveal stagger 60ms.
- Widget loops start when in view, pause offscreen, run forever otherwise. This is the region's live-element budget: three loops on screen at once max, all quiet.
- Reduced motion: settled frames (row checked, bars grown, calendar static), zero looping, entrance reveals settle instantly.
